# 内置生图提示词

## 调用链
聊天、朋友圈、情侣空间交换物品图片、杂志封面调用 `IdealMachineImageAPI.generate`，在 `apps/shengtu.js` 中统一组装提示词，再 POST `/images/generations`。已登录且目标符合代理协议时，通过现有 Cloudflare `/api/image-proxy` 原样转发请求，不再次注入；否则直连。朋友圈已有画面分析文本请求继续使用，新增系统没有网络分类请求。分类说明和示例只保留在配置中，不发送给生图 API；每次只读取并发送共享规则和当前选中的人物/非人物正负模块。

配置：`config/image-prompts.txt` 为完整原文，`apps/image-prompt-library.js` 为生成的 共享、人物、非人物正负面及优先级配置。运行 `python3 scripts/build-image-prompts.py` 更新配置；同时更新 index.html 中配置脚本版本号并发布。

逻辑：`apps/image-prompt-system.js`。本地保守规则先排除否定、昵称、比喻及条件性外观说明；朋友圈已有画面方案存在时优先分类该方案。按人物与非人物两类做本地判断；混合场景组合两类。昵称、比喻和否定内容不会触发额外主体类别。规则分类无法达到大语言模型的完整语义理解，复杂歧义会保守降级，后续可在 classify 中补充案例。

组装顺序：原始输入原样保留在首部 → 简短用户优先级/任务约束 → 全局正面 → 人物/非人物正面 → 原有自定义正面。负面单独去重组装：全局负面 → 人物/非人物负面 → 原有自定义负面和单次请求负面。extended 协议使用已有 negative_prompt；其他协议将负面作为有条件的避免事项附在 prompt 后。明确指定的文本、疲惫、衰老、特殊风格等优先于优化。没有增加参数或修改 Key 存储。

旧聊天/朋友圈通用写实词被本套配置替换，以避免旧 CGI 禁令与新 3D/插画规则冲突。各入口原有画面规划和人物身份约束保留。页面视觉与设置界面没有变化。

## 能力边界
当前传输链只支持文生图，没有参考图输入、掩膜或 images/edits 请求。模块预留 reference/edit/style 任务约束，参考/局部编辑只应用全局并限制变化范围；这些是提示词组装能力，不代表新增了图片编辑 API。当前无法验收真实参考图一致性或局部编辑效果。

内置词不在用户界面显示。项目为前端静态应用，浏览器源码及网络请求仍可查看；若要求保密，需后端生成请求而非前端配置。

## 验收
`node --test tests/image-prompt-system.test.cjs` 验证主要分类、原文保留、比喻/否定、风格隔离、参考/局部编辑任务约束，以及真实 generate 函数的模拟 HTTP 请求。没有调用收费生图 API，不能代替图像效果验收。
